# Releasing

1. Increment `versionCode` and `versionName` in `app/build.gradle.kts`, and `<Version>` in `companion/UsageNotch.Link.csproj` when Link changes.
2. Run `./gradlew clean :app:testDebugUnitTest :app:lintDebug :app:assembleSmoke :app:assembleRelease`. Build the companion and run `--self-test` under a Windows user with DPAPI support. Copy `companion/bin/Release/net8.0-windows/relay-fixture.json` to `app/src/test/resources/` if the relay format changed.
3. **Launch-test the optimized build on a real Android runtime.** Robolectric runs the unminified debug build, so it cannot catch code that R8 removes. Install `app/build/outputs/apk/smoke/app-smoke.apk` on an emulator or phone, open it, and confirm `adb logcat -b crash` is empty. 1.0.0 shipped a launch crash that only this step catches. CI runs the same check on every push.
4. Sign the APK with `packaging/Sign-Android.ps1 -UnsignedApk app/build/outputs/apk/release/app-release-unsigned.apk -OutputApk artifacts/UsageNotch-VERSION.apk`. Don't pipe its output through `2>&1` in Windows PowerShell 5.1: JDK warnings on stderr then become terminating errors. The local release key lives outside the repository, under `%LOCALAPPDATA%\UsageNotch\AndroidSigning`, and its password is protected with Windows DPAPI for the current user. Keep an encrypted private backup of that directory. Never regenerate the key for an existing package, print its password, or upload private material.
5. **Verify the signed file is the build you intend to ship.** Run `apkanalyzer manifest version-name` and `version-code` on the signed APK and compare them with step 1. 1.0.1 was signed from a stale 1.0.0 build because this check was missing. Confirm the signer certificate SHA-256 is `ddafa1fb472f7ee28c91c7badab1930e5ba9b8a7e78b96ad33bec36798148091`. Install the signed APK over the previous release on an emulator and launch it.
6. Publish the companion: `dotnet publish companion/UsageNotch.Link.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -p:DebugSymbols=false -o artifacts/link-VERSION`. Run the published `UsageNotch.Link.exe --self-test`, then delete the files it writes (`verification.txt`, `test-certificate.cer`, `relay-fixture.json`).
7. Zip `UsageNotch.Link.exe` with `packaging/LINK-SETUP.md` (as `SETUP.md`). Don't include identity files, pairing exports, test databases or user history. Write `SHA256SUMS.txt`.
8. Create the GitHub release with the APK, companion ZIP and checksums. Download the uploaded assets and compare their SHA-256 with `SHA256SUMS.txt`.

The public CI compiles, tests and launch-tests the smoke build. It doesn't have the private signing key, so CI artifacts can't update a release-signed installation. Android's package installer checks that each update is signed with the same certificate as the installed app.

The Windows companion isn't Authenticode signed, so Windows SmartScreen may warn on first launch. No silent Android package installation, root access or bypass of Android installation approval is used.
